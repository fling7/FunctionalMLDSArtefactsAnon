# Implementation independence

Implementer-A and Implementer-B were fresh subagents with no inherited conversation history. Each initially received only its own directory containing SPEC v1, the native schema, example instance, example trace, and handwritten fixtures. Prompts and hashes are in logs/agent_prompts/. Dated amendments were delivered equally to both after they reported gaps.

Achieved: L2 as the brief defines procedural subagent isolation: separate contexts, initial data-only directories, explicit allowed-file lists, no network use, and prompt hashes. This was not an operating-system-enforced filesystem or network boundary: agents shared the host and were instructed to restrict access. Their file-access and correction records are in independent/*/WORKLOG.md and ambiguities.md. The same orchestrator authored the specification, and the same model family likely produced both implementations. Independence is of implementation, not specification.

A uses independently parsed native JSON and Python. B independently reads native JSON and executes admission decision logic in clingo ASP. Cedar was probed but did not support the attempted cardinality/existential formulation through the installed API; fallback evidence is in B's work log. Neither implementation saw the backend or the other's code. Root copies implementations without edits into verification/impl_a and verification/impl_b; later corrections must return to the original implementer.

Initial author clarifications A-001 through A-003 precede differential evaluation and remain separately documented from observed disagreements. Raw differential records retain code hashes, inputs, verdicts, and every disagreement. An initial agreement figure is not a claim of specification validity.

The original B implementer later prepared an optional immutable-model compiled API in its same restricted directory. It partitions the unchanged ASP rules mechanically, prepares model-only facts, and creates a fresh solver and schema check for each request. The adapter and ASP sources remain unchanged. Its retained evidence covers 827 exact-output comparisons over 71 snapshots; separate integration tests compare all backend variants before adoption. This is an engineering optimization, not an additional independent implementation or new corpus observation.

The anonymous artifact retains the initial prompts, original evaluator sources, own tests, supplied inputs, ambiguity records, and the compiled API's source and comparison trail. Identifier anonymization and digest repinning are recorded as transformations of copies. Canonical keys for embedded instance/trace snapshots are recomputed together with all referring comparison and summary records; file hashes are not substituted for these content keys. Descriptive absolute paths in the supplied example trace are interpreted relative to the original deployed project and replaced consistently by project-relative names across every duplicate. The independent evaluators consume the supplied JSON and do not dereference those auxiliary paths.

A bounded export check ran both implementations' own self-tests and all 827 saved comparisons against the transformed compiled implementation, with exact agreement. This checks preservation of those observations after export, not completeness over all possible inputs. An additional non-adopted bulk-fact prototype exposed an unsupported control-character literal during compilation; its failures and integration fallback audit are retained separately. The original 827 comparisons must not be described as a universal equivalence proof.

The frozen WP6 integration bridge catches compilation failures and delegates to the unchanged original B adapter. Three separate carriage-return identifier cases each matched the original adapter on two repeated calls, with the temporary bindings restored. The retained audit examined decoded keys and string values in 780 baseline/prepared-mutant projects (1,560 native and trace files) and found no listed line-splitting control character. This bounded integration evidence is in results/raw/wp6_control_character_audit_v2/report.json with a separate provenance join; it neither repairs the standalone compiled API nor covers future inputs.
