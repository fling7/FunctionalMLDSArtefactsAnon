# Mutation analysis

Generated by `experiments/report_mutation_analysis.py` from preserved raw WP6 runs. The preregistered endpoint classifies ownership/action faults relative to SPEC and its amendments. Reachability restrictions and consistent changes in ownership are separate outcomes. Each mutant is a unit; probes within it are correlated. No mutant is counted as a new room.

## Scope and authority

The authoritative routing contract is `docs/SPEC.md` with `SPEC_AMENDMENT_A001.md`, `A002.md`, and `A003.md`. I1 defines the candidate label and I2 must agree on every normal verdict. Unresolved models are excluded explicitly. The structural and authoring validators enforce additional publication constraints; disagreement with the narrow routing endpoint is not automatically a validator bug. A publish-time table can implement the same routing decisions, while digest, request schema and commit obligations remain runtime concerns.

V-b includes direct native schema/domain checks and a separately labelled legacy validation view with retained checked-element counts. Placement and knowledge traceability metrics lack their original authoring inputs and remain not applicable. Strict unions cannot claim a pass through unavailable constituents.

The real SessionStore admission path executes with a ScriptedClient. These results measure deterministic admission and rejection atomicity. They do not measure language-model quality, latency, HTTP commit/evidence behavior or a deployed Unity client.

## Remaining evidence and interpretation

B0/B1 language-model routing on a stratified mutant subset and independent language-model judgments of consistent swaps are not executed by this harness. Geometric evidence is reported only for explicitly supplied separate snapshots above. Missing outcomes cannot be inferred from ScriptedClient results. Generated-room and natural-evolution coverage is present only when it appears in the raw run inventory above. The supplied classroom alone does not support population-level generalization to generated rooms. Native case IDs identify snapshots; cross-model counterparts and repeated snapshots of one source room are not distinct rooms. Every mutant-to-source join and supplied manifest hash is retained in the paper-input inventory; unresolved joins never create a room. Preregistered Wilson intervals describe mutant units and do not remove source dependence. Separate exploratory percentile bootstrap intervals resample whole resolved sources with all their snapshots/mutants together; fewer than two source clusters is undefined.

The first-match and reach-only comparisons are real executions through the same backend configuration points. Loader refusal prevents a session from existing and is kept separate. Table/runtime equality is an equivalence finding for executed pairs, not a claim that runtime routing checks outperform a table.

Reproduce this document with `python experiments/report_mutation_analysis.py --run-dir <raw-run> [--run-dir <another-run>] --source-manifest <path>=<sha256> [--source-manifest <another-path>=<sha256>] [--geometry <geometry-json>]` using the exact manifest paths and hashes in the paper-input source_manifest_pins array. The immutable raw files and preregistered summary remain authoritative. Reporting metadata is exported to `paper_inputs/wp6_mutation_summary.json`; all generated tables are referenced here and in that inventory. Superseded progress-snapshot tables remain explicitly indexed as audit history, not final evidence.
