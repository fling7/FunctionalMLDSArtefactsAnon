# WP7 preregistration supplement

Status: PROPOSED; evaluation must wait for the coordinator's hash freeze. Unit tests may run before the freeze. This supplement fixes offline tests; natural-pair analyses require the separately frozen WP5 corpus. No mock output will be described as real-model evidence.

## Protocol and assumptions

Compare packet check-before-lock, cooperative publication with a shared per-project OS lock and generation/hash manifest published last by atomic replace, and uncooperative direct edits. Cooperative publishers hold the same lock throughout projection replacement and final generation flip; commit reload, compare, and journaled evidence append hold it continuously. Generation is a monotone integer. The consistent loader reads marker, verifies every manifested projection, loads/validates the backend contract, verifies projections again, and rereads marker, retrying on changed generation. Interrupted in-place publication is refused. Initial publication explicitly bootstraps generation 1. Filesystem atomic same-volume replace, truthful fsync, advisory-lock cooperation, and stable local paths are assumptions; uncooperative writes and power-loss directory durability are separate limits.

## Fixed offline evaluation

1. Exhaustive finite-state interleavings for publishers in {1,2}, sessions in {1,2}, each publishing once and each session attempting one commit. Five projection writes, a generation flip, snapshot, admission read, validation, lock, comparison, paired append visibility, restore, and unlock are modeled. Record reachable states, transition edges, complete schedule count, violating schedule count, and first counterexample. The abstraction is not a proof of Python or OS implementation.
2. Actual production publication and append paths: 50 simultaneous sessions in each of thread and process runs, protocols {packet,cooperative}, fixed random seed 20261015, scripted uniform generation latency 10 to 50 ms, five timed publications. Observe events at append; retain outcomes and timing per session. A controlled scheduling barrier separately forces the check/append race for packet and direct-edit publisher, without pretending it is naturally frequent.
3. Partial publication: baseline and prefixes 1 through 5 of writes {instance,trace,agents,project,placement}, then complete marker flip. Both coherent complete publication and every interrupted prefix are loaded with the production consistent loader; outcome must be a coherent generation or E_PUBLICATION_INCONSISTENT. Placement is an explicit project-local projection because the packet has no standalone placement file in its project directory.
4. Append exception, process termination, and partial-write injection at each exposed durable transition: before journal, after journal, after event partial/write/fsync, after validation partial/write/fsync, before journal clear, after journal clear. Each cell runs once on a fresh project with baseline paired records. Recover under the project lock, require parseable JSONL and both-or-neither IDs. Commit linearizes at durable journal removal for cooperating readers; unlocked raw readers can see an intermediate file and are outside the interface. Session rollback is exercised against the actual store for ordinary exceptions. Process termination destroys the in-memory store, so restoration across restart is not claimed. Restore-step faults are separately reported, including partial restoration if found.
5. External effect: local append-only sink records an effect before an intentionally rejected commit, demonstrating non-rollback; after-commit ordering suppresses that effect on rejected commits and emits on successful commits. It is not a transactional outbox or exactly-once external delivery claim.
6. Between-turn publication: compare optional generation pre-call check enabled/disabled, recording actual scripted-client invocation counts. Packet already performs authoritative pre-call contract revalidation; do not claim the optional check avoids calls that packet already avoids. Report same-generation direct edits separately.
7. Fingerprint scopes F0/F1/F2/F3: all available frozen natural pairs plus synthetic metadata, persona, KB, persona-injection-style, trace, instance and deletion edits. Each synthetic edit retains a distinct row; no empirical deployment frequency or natural fault claim. F2 is canonical routing decisions plus declared action set, F3 adds prompt projection. Routing-changing labels must come from frozen independent implementations, or remain explicitly unlabelled pending that input. Without natural pairs, report synthetic-only partial completion.
8. Availability: at least 50 sessions under scripted republication for F1 and F2, each supplied change with routing label when available. Generation equality is mandatory in strict cooperative mode even when a scope hash stays unchanged; scope-only comparison is a separately labelled relaxed-generation experiment, not the strict protocol guarantee.

## Reporting

Each invocation creates a unique raw run directory; previous raw evidence is never overwritten. Processed numbers derive only from stored row data and explorer state/schedule counts. Keep platform/runtime, source hashes, seed, script latency, faults, exception codes, and exact outcome totals. Report partial or blocked scope honestly when inputs or budget are unavailable. No confidence interval for exhaustive synthetic schedules or deterministic fault cells; stress counts are workload observations, not population rates. Hash this file before evaluation and append deviations rather than rewriting frozen content.
