# SPEC amendment A-001
Date: 2026-10-15. Trigger: independently reported ambiguities from Implementer-A and Implementer-B before their decision implementations. These are specification-author decisions, not claims of specification independence. SPEC v1 remains unchanged.

1. The admission evaluator operates on a supplied pinned session and parsed model; it compares the request's model_sha256 against session.model_sha256 as case-insensitive hexadecimal strings. It does not compare the request to a newly published model or recompute the file digest from a parsed mapping. File loading validates declared digest separately. Raw bytes are the baseline scheme; a later portable scheme may normalize CRLF only.
2. At least one of entity_id, source_object_id, source_id must identify one scene object. Each supplied identifier must resolve uniquely. When both source aliases are supplied, they must agree. All supplied identifiers must identify the same object. Unknown entity/source or nonunique source gives E_UNKNOWN_ENTITY; disagreement among otherwise valid identifiers gives E_ID_MISMATCH.
3. Gate 1 digest precedes identity checks. Within the identity/selection condition, check selection validity, then existence/uniqueness of IDs, then their consistency. state must be resolved. ambiguous=true or ambiguity=true rejects. For object-valued ambiguity, a truthy ambiguous or is_ambiguous key rejects; other nonempty fields alone do not declare ambiguity. A supplied candidate_entity_ids list must equal the singleton selected entity; empty or duplicate lists reject with E_SELECTION_STATE. Unknown fields and invalid types are schema failures at the final schema condition, except malformed selection structures necessary to resolve identity reject with E_SELECTION_STATE.
4. Validate active_agent_id after selection and before ownership: it must match an Agent.sourceAgentId, else E_ACTIVE_AGENT_UNKNOWN. In optional server_strict mode, after membership check require equality to session.active_agent_id, else E_ACTIVE_AGENT_MISMATCH. Client mode does not compare to server state. Explicit switches are a separate operation.
5. Group membership for resolution uses the scene object's objectGroup reference list. sourceGroup is descriptive. Group sourceObjectId is a consistency projection and does not add groups. Zone membership uses zone.sourceObjectId containing the object's sourceId. Owners at each level are sets of agent IDs, so one agent owning multiple relevant groups remains one owner. No fallthrough after a nonempty ambiguous deciding level.
6. An answering capability use must target the exact scene-object entity; group/zone-only target declarations do not satisfy (p,t). Independently verify native ScenarioStep -> CapabilityUse -> Capability -> RuntimeBinding -> RuntimeAction links. Answering actions are designated by input schema applicationActionKind=chat or endpoint locator POST /chat. Ignore unrelated infrastructure actions when selecting an answering chain. Require one answering use, one Capability reference, one answering binding, one answering action, and one ScenarioStep referencing that use. The provider must list the capability in providedCapability. Missing/broken selected path gives E_NO_DECLARED_ACTION; multiple selected answering paths give E_ACTION_AMBIGUOUS.
7. Native declarations are authoritative. The selected path must have one exactly matching trace projection for its step/use/capability/provider/binding/action and target list (compare target sets), designated chat. Missing or inconsistent selected projection gives E_NO_DECLARED_ACTION; duplicate selected trace entries give E_ACTION_AMBIGUOUS. Do not use a trace-only path as authority. modelBinding metadata in a schema is descriptive to this evaluator; the native path is checked independently.
8. Global publication validation is separate from admission. The evaluator can report E_PUBLICATION_INCONSISTENT for unparsable top-level inputs, non-object records, or duplicate native object IDs. It must not replace a selected-path admission rejection with a global authoring-validator error. Differential analysis will report setup refusals separately from admitted-session routing decisions. Small fixtures intentionally omit unrelated authoring scaffolding.
9. Final schema checking uses the declared input schema of the selected action on the complete wire request. It follows all preceding conditions. On admission return the wire provider sourceAgentId and RuntimeAction ID; on rejection return null provider/action.
